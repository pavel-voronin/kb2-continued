# Игра в браузере

Локальная статическая страница, готовая для последующего размещения на GitHub Pages. Ничего не публикуется автоматически; workflow публикации не добавлен.

Из корня репозитория:

```powershell
python -m http.server 8008 --bind 127.0.0.1 --directory WEB/dist
```

Откройте http://127.0.0.1:8008. Через `file://` эмулятор не работает.

Кнопка давности обновления появляется только у «Продолжения»: «Обновление: сегодня», «Обновление: вчера», «Обновление: 2д назад» и далее, по календарной дате в браузере. Она открывает историю изменений поверх игры, в том же размере и с растровым шрифтом из `KB2.FNT`. Игра на это время приостанавливается. Закрытие — повторное нажатие кнопки давности обновления, «Закрыть» или Escape. Длинный список прокручивается внутри неподвижной рамки колесом, стрелками и Page Up / Page Down; полоса появляется только при переполнении. Выделение текста на странице отключено.

Последняя открытая версия запоминается в `localStorage` (`kb2.changelog.lastViewedVersion`). При первом посещении и при появлении более новой непросмотренной версии кнопка подсвечивается жёлто-оранжевым свечением с мягкой пульсацией. Открытие истории версий отмечает текущую версию просмотренной и убирает подсветку; состояние синхронизируется между вкладками. При отключённой анимации в настройках браузера свечение остаётся статичным.

Источник текста, номера версии и даты обновления — корневой `CHANGELOG.md`. Первый заголовок релиза имеет вид `## 1.0.0 — 2026-11-11`. После изменения файла обновите локальную страницу без пересборки DOS-игр:

```powershell
node WEB/prepare-page.cjs
```

Полная сборка также обновляет changelog автоматически. Шрифт и текст включаются в статическую страницу; дополнительные серверные обработчики не нужны.

`dist/` содержит готовую страницу, обе игры и локальный runtime **DOSBox-X из js-dos emulators 8.5.3**. CDN и серверная часть не нужны; пути относительные, поэтому работают и под `/kb2-continued/` на Pages.

## Пересборка

Нужны Node.js и npm. Ядро DOSBox-X собирается в Linux/WSL с Git, CMake, Ninja и активированным Emscripten 5.0.2. Сначала установите зависимости страницы, затем соберите ядро:

```sh
cd WEB
npm install
bash runtime/build.sh
```

Результат ядра сохраняется в `.build/runtime/`. Затем в папке `WEB/`:

```powershell
node build.cjs
```

Сборщик запускает оригинальный Turbo Pascal 7.0 в DOSBox/WASM, собирает `KB2.PAS` и `RSPACK.PAS`, упаковывает ресурсы. Classic берётся из локальной ветки `main`, Continued — из текущего рабочего дерева `SRC/`. Исходники игры не изменяются. Коммит Classic и хеши EXE записываются в `dist/games/builds.json`; журналы компилятора — в игнорируемой `.build/`.

Исходники ядра закреплены на [emulators v8.5.3, e6f4e54](https://github.com/js-dos/emulators/tree/e6f4e5449a5b17ae3ea0fdccfd453c8d299e9ea5), с подмодулем [DOSBox-X 788fde9](https://github.com/js-dos/dosbox-x/tree/788fde99d3d451eab3621009186e5abe516f2b9c). Локальные патчи находятся в `runtime/`: включают штатный `fastlaunch`, сохраняют установку текстового режима 3 для EGA перед пропуском заставки и исправляют запись определения CMake. `package.cjs` добавляет к собранному ядру штатную обвязку Worker/Sockdrive из установленного пакета 8.5.3. Патчи и скрипты поставляются вместе с ядром в `dist/vendor/`. Адреса JS/WASM и игровых архивов содержат хеш содержимого, поэтому исправленный runtime не подменяется старой копией из кеша. HTML предварительно загружает JS/WASM параллельно с архивом игры.

`startup_cycles:30000` однократно ускоряет загрузку картинки и рисование меню. Ускорение включается только при запросе `KB2.EXE` на EGA-режим 0x10, после инициализации модулей Pascal и калибровки `Crt.Delay`. При первом блокирующем BIOS-чтении клавиши (INT 16h, AH=00h/10h) ядро восстанавливает исходные 3000 циклов и сообщает странице о готовности. Поэтому игровой звук и дальнейшие задержки выполняются с обычной скоростью. Аудиокод не изменён. Оболочка ждёт это событие вместо опроса программы раз в 100 мс. Исходники и EXE обеих игр не меняются.

При первом запуске Classic проверена на совпадение EXE с оригиналом из `KB2-DOS.zip`: SHA-256 `c24025eb398a1c4a960b4ab7a21abb6fb81c86041f988178979381bfd8766a06`.

## Поведение

- Версия игры выбирается в dropdown. При первом открытии выбрано «Продолжение» и автоматически запускается Continued; затем восстанавливается выбранная версия из localStorage браузера. Служебные экраны скрыты до появления цветного кадра `KB2.EXE`. Выбор новой игры и сложности остаётся за игроком.
- До готовности игры виден оригинальный титульный кадр с именем автора: `assets/startup.png`, снятый из DOSBox-X в области 600×330. Сборка встраивает PNG в HTML без отдельной загрузки. Изображение занимает ровно область игрового canvas и заменяется живым кадром без анимации и изменения размеров; текст «Загрузка…» поверх него не показывается. При повторном запуске заставка появляется снова.
- Масштаб выбирается в списке от 100% до 150% с шагом 10%; по умолчанию 100% (600×330 CSS-пикселей). Маленькое окно прокручивается, выбранный размер не уменьшается молча. Масштаб браузера дополнительно влияет на физические пиксели.
- Веб-окно показывает верхние левые 600×330 пикселей исходного EGA-кадра 640×350: пустые правые 40 и нижние 20 пикселей исключены из вывода. Исходные ресурсы и EXE не меняются. В меню проверено отсутствие цветных пикселей за границами этой области; та же область содержит исходные экраны TITL, TOWN и YOULOSE.
- Full screen и F11 при фокусе страницы включают fullscreen с пропорциональным fit. Escape выходит. Если фокус в адресной строке, F11 управляет самим браузером: страница тоже переходит в fit, но выход из браузерного fullscreen — повторным F11.
- Физическая клавиатура использует позиции клавиш (`KeyboardEvent.code`), независимо от русской/английской раскладки. Потеря фокуса отпускает зажатые клавиши.
- Версия игры, масштаб и включение звука запоминаются в localStorage этого браузера. При отключённом хранилище страница работает с настройками по умолчанию. Полный экран не восстанавливается автоматически. Если звук был включён, после открытия страницы он активируется при первом нажатии клавиши или мыши, в соответствии с ограничениями autoplay.
- Браузер использует `emulators.dosboxXWorker`, чтобы PC Speaker воспроизводился ядром DOSBox-X, как в отдельном окне.
- Звук выводит штатный AudioWorklet js-dos (`audioWorklet: true`); кнопка использует `ci.mute()` / `ci.unmute()`. Собственной очереди PCM, отдельных AudioBufferSource и второго AudioContext в оболочке нет. При смене версии `ci.exit()` освобождает старый аудиовывод. В конфигурации задан `[mixer] rate=44100, prebuffer=0`: в прежнем ядре DOSBox стандартный prebuffer в emulators 8.5.3 вызывал избыточную генерацию PCM и накопление задержки. За примерно 5 секунд контрольного запуска до исправления генерировалось 5,58 секунды PCM, после — 5,02 секунды. Это проверка темпа потока; фактическая задержка устройства вывода в неё не входит.
- Экран проигрыша с башней в обеих версиях статичный и без собственного звука: игра ждёт любую клавишу, затем завершает DOS-программу. Авторского возврата в меню нет.
- «Игра с диска» открывает выбор файла `.KB2` или `KB2.DAT` в браузере. Перед импортом проверяется размер оригинального формата — 27 729 байт. Файл помещается в виртуальный DOS как `WEBGAME.KB2`, кеш каталога обновляется, а единственный выбранный файл передаётся оригинальному меню игры. Отмена выбора оставляет игру в меню. Поиск без выбранного файла завершается безопасно: оригинал обрабатывает ошибку 2, но при ошибке 18 использует неинициализированное имя и портит память.
- Именное сохранение скачивается после закрытия записанного `.KB2`; быстрое сохранение клавишей S выгружает `KB2.DAT`. Начальная запись новой кампании и техническая запись после загрузки файла не скачиваются. После завершения DOS-программы страница автоматически запускает ту же версию заново, показывая титульную заставку до меню. Промежуточного экрана завершения нет; перед остановкой старого ядра оболочка дожидается выгрузки сохранения. Формат файлов и EXE обеих версий не изменены; мост реализован в веб-оболочке и патчах ядра `jsdos-integration.patch`, `save-files.patch`, `startup-keyboard.patch`.
- Переключение версии и обновление страницы сбрасывают сеанс. Постоянное хранение DOS-сохранений пока не реализовано.
- Адрес Discord задаётся в `index.html`: https://discord.gg/ausmfCeyP.

## Дальнейшее управление мышью

Простая передача DOS-mouse-событий не поможет: игра читает BIOS-клавиатуру и не использует мышь. Экранная панель клавиш удалена по запросу; игра управляется клавиатурой.

Для кликов прямо по изображению можно добавить профиль экранных областей: координаты нормализуются к 640×350, затем область превращается в клавишу. Для карты, меню, боя и диалогов нужны разные профили; без знания текущего экрана один и тот же клик будет неоднозначным. Для Continued надёжнее небольшой мост, сообщающий оболочке только текущий тип экрана и доступные действия; игровая логика остаётся на Pascal. Classic сохраняет внешний слой без изменений EXE. Автоматический путь до выбранной клетки — отдельная игровая функция, её здесь нет.

## Проверено

Для файлового моста обе оригинальные сборки EXE прогнаны в поставляемом DOSBox-X/WASM: выбор «Игры с диска» при пустом каталоге возвращает запрос браузеру и оставляет рабочее меню; импорт 27 729 байт побайтно совпадает с выбранным файлом и повторно записанным `KB2.DAT`; S закрывает быстрое сохранение; F10 → подтверждение выхода/сохранения → имя файла создаёт `.KB2` того же размера и сообщает о завершении игры. На реальной локальной странице пользователь подтвердил скачивание `KB2.DAT` клавишей S и последующую загрузку этого файла через «Игру с диска». Отмена выбора, отклонение неверного размера, передача точных байтов, отдельные выгрузки быстрого/именного файла и уведомление о выходе также проверены исполнением клиентского файлового моста с DOM-заглушками. Хеши обоих EXE остались прежними.

При последующей оптимизации реальный браузер показал полностью нарисованное меню на 357-й миллисекунде против 774,6 мс в контрольном запуске. Возврат к 3000 циклам подтверждён сообщением ядра на 337,9 мс. Этапы: страница/архив 67,7 мс; подготовка ядра 134,1 мс; DOS/Pascal до графического режима 92,6 мс; отрисовка меню 43,5 мс; полный кадр ещё через 19,1 мс. Прежние 597,5 мс относились к первому частичному кадру, а не полностью готовому меню. В Node для обеих версий итоговый RGB-кадр совпал с обычным запуском (SHA-256 начинается с `bdb218942f41f782`), а Enter после восстановления скорости открыл следующий экран. Временные метки после проверки убраны.

После включения `fastlaunch` с инициализацией EGA обе игры дошли до цветного кадра в Node. В реальном браузере локальной страницы контрольный замер показал первый игровой кадр через 597,5 мс от начала навигации (прежде 1641,4 мс). Между готовностью ядра и обнаружением `KB2.EXE` прошло 101,1 мс вместо прежних 1100,7 мс. Пользователь подтвердил появление меню. Это отдельные локальные замеры с кешированными ресурсами, а не гарантия времени первого скачивания. Временное профилирование после проверки удалено из страницы.

До упрощения страницы в Chrome проверены запуск обеих версий, клавиатурный Enter, начало новой игры, fullscreen кнопкой и F11 с фокусом страницы, выход Escape и переключение Classic → Continued. После упрощения проверены синтаксис JavaScript, содержимое страницы и ответ локального HTTP-сервера. После переключения на DOSBox-X проверен запуск обеих сборок через поставляемые файлы runtime (640×350, цветные кадры); аналог `PlayCue(5)` из неизменённого KBSOUND.PAS ранее сравнен с настольным DOSBox-X. Переключение на штатный AudioWorklet проверено программно: включение параметра, восстановление настройки, mute/unmute и вызов exit при смене версии. Повторная браузерная проверка и прослушивание недоступны: инструмент управления браузером не запускается.
